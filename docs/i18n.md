# i18n — a userland pattern

[中文 → i18n.zh-CN.md](i18n.zh-CN.md)

Mist has no i18n intrinsic, and does not need one: a locale store plus a
plain `t` helper covers templates and JS with the machinery you already
know. This page is the whole recipe.

## The locale store

`stores/locale.ts` — a persisted store for the current locale, the
dictionary, and a `t` helper that reads through the store:

```ts
import { store } from 'mist'

const dict = {
  en: { 'cart.title': 'Cart', 'cart.checkout': 'Checkout' },
  zh: { 'cart.title': '购物车', 'cart.checkout': '结算' },
}

export const locale = store('en', { persist: 'locale' })

export function t(key: string): string {
  return dict[locale.value][key] || key
}

export function setLocale(next: string) {
  locale.value = next
}
```

Pick the initial locale from the device with
`wx.getAppBaseInfo().language` in `onLaunch` if you prefer following the
system over persisting a choice.

## Using it in pages

```jsx
---
import { t, locale, setLocale } from '../stores/locale.ts'

function toggle() {
  setLocale(locale.value === 'en' ? 'zh' : 'en')
}
---
<div>
  <span>{t('cart.title')}</span>
  <button onTap={toggle}>{t('cart.checkout')}</button>
</div>
```

Template calls like `{t('cart.title')}` hoist to generated deriveds (the
normal rule — see [language.md](language.md)), recomputed per update batch,
so every string re-renders the moment the locale changes.

**Import `locale` alongside `t`, always.** The store subscription comes
from importing the store itself; a page that imports only `t` compiles
fine but never subscribes, so its strings freeze at first render. Listing
`locale` in the import is what wires the re-render.

## Config strings — nav and tab bar titles

`config` values are static literals by design; they ship in the default
language. Retitle at runtime in `onShow`:

```ts
import { onShow } from 'mist'
import { t, locale } from '../stores/locale.ts'

onShow(() => {
  wx.setNavigationBarTitle({ title: t('nav.cart') })
  wx.setTabBarItem({ index: 0, text: t('tab.home') })
})
```

`onShow` runs on every navigation back to the page, so titles stay correct
after a locale switch elsewhere. The default-language title is visible for
a frame on cold start — that flash is inherent to the platform (WeChat
reads `.json` config before any JS runs).

## Cost note

Localized strings ride `data` like any bound value — each visible string
is one hoisted derived, serialized over the bridge when it changes. A
locale switch re-sends every visible string at once; for a normal page
(tens of strings) that is one small `setData`. Keep the dictionary itself
out of state — in the pattern above it is a plain module constant, and
only the *resolved* strings cross the bridge.
