# i18n——一个用户层模式

[English → i18n.md](i18n.md)

Mist 没有 i18n 内建能力，也不需要：一个 locale store 加一个普通的 `t`
辅助函数，用你已经熟悉的机制就能覆盖模板和 JS。这一页就是完整配方。

## locale store

`stores/locale.ts`——持久化的当前语言 store、字典，以及一个通过 store
读取的 `t` 辅助函数：

```ts
import { store } from 'mist'

const dict = {
  en: { 'cart.title': 'Cart', 'cart.checkout': 'Checkout' },
  zh: { 'cart.title': '购物车', 'cart.checkout': '结算' },
}

export const locale = store('en', { persist: 'locale' })

export function t(key: string): string {
  return dict[locale.value][key] || key
}

export function setLocale(next: string) {
  locale.value = next
}
```

如果想跟随系统语言而不是持久化用户选择，可在 `onLaunch` 中用
`wx.getAppBaseInfo().language` 取设备语言作为初始值。

## 在页面中使用

```jsx
---
import { t, locale, setLocale } from '../stores/locale.ts'

function toggle() {
  setLocale(locale.value === 'en' ? 'zh' : 'en')
}
---
<div>
  <span>{t('cart.title')}</span>
  <button onTap={toggle}>{t('cart.checkout')}</button>
</div>
```

模板中的 `{t('cart.title')}` 调用会被提升为生成的 derived（常规规则——见
[language.zh-CN.md](language.zh-CN.md)），每个更新批次重新计算，因此语言
一切换，所有字符串立即重新渲染。

**永远把 `locale` 和 `t` 一起导入。**store 订阅来自导入 store 本身；只
导入 `t` 的页面可以编译，但永远不会订阅，字符串会冻结在首次渲染。在
导入列表中写上 `locale` 才接通了重渲染。

## 配置字符串——导航栏与 tab bar 标题

`config` 的值按设计是静态字面量；它们以默认语言发布。在 `onShow` 中运行时
重设标题：

```ts
import { onShow } from 'mist'
import { t, locale } from '../stores/locale.ts'

onShow(() => {
  wx.setNavigationBarTitle({ title: t('nav.cart') })
  wx.setTabBarItem({ index: 0, text: t('tab.home') })
})
```

`onShow` 在每次导航回到页面时都会运行，因此在别处切换语言后标题仍然
正确。冷启动时默认语言的标题会闪现一帧——这个闪现是平台固有的
（微信在任何 JS 运行前先读 `.json` 配置）。

## 成本说明

本地化字符串像任何绑定值一样进入 `data`——每个可见字符串是一个提升的
derived，变化时通过桥序列化。切换语言会一次性重发所有可见字符串；对
普通页面（几十个字符串）来说只是一次小的 `setData`。字典本身不要放进
state——上面的模式里它是普通模块常量，只有*解析后*的字符串会过桥。
